# Port status - Spice Bandits

Architecture: the armv7 Mach-O runs under Unicorn inside `host/ra_host`, with iOS implemented on the host (SDL2, desktop GL, a mini Objective-C runtime, a small UIKit, CoreGraphics, Foundation). Only `Spice Bandits 1.14.ipa` (decrypted) is usable; the `...hd...ipa` is FairPlay-encrypted.

## What works (verified by screenshots in `tests/`)
| area | state |
|---|---|
| Boot | Mach-O (PIE) load, dyld binds, **module initialisers** (C++ statics), UIApplicationMain, `MainWindow.nib` |
| Nibs | **NIBArchive loader** (`host/uikit.inc`): all UIKit classes used by the 44 nibs, outlets (setter/ivar/host property), actions, class swapping, `initWithCoder:` via a fake NSCoder |
| UIKit | view tree, frames/transforms/alpha, autoresizing, `layoutSubviews` pass, images (**Apple CgBI PNG decoder**), labels/fonts (FreeType via SDL_ttf, bundle fonts), buttons + target/action, scroll views, view controllers + modal present/dismiss, animations (run immediately), `CADisplayLink`, notifications, hit-testing |
| CoreGraphics | software bitmap contexts (CTM, DrawImage, FillRect, text), `UIGraphics*` image contexts, geometry helpers |
| Foundation | arrays, dictionaries, data, numbers, strings, dates, character sets, URLs, files, errors, locale, bundle (`host/foundation.inc`); ObjC **categories** |
| C++ runtime | libstdc++ subset: COW `std::string`, red-black tree helpers, list nodes, stringstream (`host/cxxabi.c`) |
| System | zlib passthrough, blocks (`Block_copy` with copy helpers) and GCD, threads run synchronously, nested guest calls (engine pool) |
| Rendering | intro splash -> loading screen -> **main menu** (Play / Career / Tech shop / Upgrades / Spicery) -> **world map** (OpenGL ES 1.1 -> desktop GL, landscape) |
| Offline game data | `offline_data.dat` (JSON) is parsed, so the player profile / shop list / medals load |
| Third-party SDKs | Tapjoy, Flurry, Burstly, AdMob, MM, InMobi, Facebook/Twitter, Crystal, AdManager are disabled (every message is a no-op returning nil) |
| Screens verified | intro splash, first-run welcome tutorial, world map (flyouts with text), **Training level**, main menu, **Tech shop**, **Career** (avatar), **Spice shop** (offline App Store catalogue), shop tabs |
| Input | mouse = touch; UIKit buttons, tabs and `Done` work; touches reach the GL view and the engine |
| Window | uses the IPA's `iTunesArtwork` as the window icon |

## Known problems
0. **Levels load and render (fixed).** Root cause of the old "loading screen never finishes": the engine's level loader runs on a pthread and reports completion by posting a request to its screen-transition object (`b29e4(cmd, 6, 0, 0xb)` in `sub_cb5d8`); that request is ignored unless the transition is idle (kind 3). The host used to run every `pthread_create` start routine *inside* the call, so the post arrived while the transition was still closing and was dropped. Threads are now cooperative (own stack, `uc_context_save/restore`, parked in `pthread_cond_wait`, woken by `pthread_cond_signal`) and are started ~20 frames after `pthread_create`, once the transition is idle. Also fixed on the way: name-less `addObserver` calls (unbound `UI*Notification` constants) fired on every notification; the guest could delete the host's render-target texture (`glDeleteTextures` id collision) which drew a giant upside-down glyph; `TutorialView` sizes itself from measured text and needs its nib children to follow (autoresize).
   - **Fixed: pause menu "To the map!" / "Replay".** Root cause: the host never ran `-[EAGLView .cxx_construct]` (and the other classes' C++ ivar constructors), which the ObjC runtime calls on alloc. `0xf5970` (the EAGLView engine constructor) allocates the modal message-box manager (`0xa99bc`) and stores it in the global `[0x47ecdc]`; without it `0xad24c` added the "Do you want to abandon the current game?" box to a null manager and the frame (`0xf7c54` -> `0xa9bf8`) never drew it. `objc_construct()` now runs `.cxx_construct` superclass-first for alloc and nib-created guest objects. "Yes" returns to the map.
   - **Fixed: white boxes on the map after a level.** The game deletes GL texture names twice (level teardown + Texture2D dealloc); the names share one GL namespace with the host's UI textures, so the second delete killed a reused id and the player bar / tutorial popup drew white. `glDeleteTextures` now only honours names the guest generated and still owns. Also the "You will level up" note hiding is limited to the small bubble view (it used to hide the whole bottom bar container).
   - **Spice is earned offline** (the game's own text: "You get spice for winning games and leveling up"; the config has `tower_rewards` sp_first 3 / sp_other 1): the host adds 1 spice per 5 xp and 10 per level gained until the win screen is hooked up. **Spice shop is free:** the product catalogue prices are $0.00, `+[InAppItemsHandler buySpice:]` is intercepted (`offline_buy_spice`) to add the pack's spice from `userData.tower_inapp` and refresh the bars; the catalogue is requested when the shop opens (the saved-profile flow never did, so the pack row was missing). Touch fix: plain `UILabel`/`UIImageView` no longer swallow taps meant for the button under them.
   - **Fixed: tech shop buying.** (1) `+[NSDictionary dictionaryWithObject:forKey:]` was missing, so the ShopItemView selection notification carried a nil userInfo and the shop ignored the tap; (2) the bottom info panel (Unlock button) is authored at y=906 in a 768x768 page and was off-screen - the bottom-anchored fix now also accepts a square parent; (3) `%@` of an NSNumber printed `<NSNumber: 0x...>` (balance label) - now prints the value. **Fixed: blank page after flipping Upgrade yard <-> Tech shop.** `vcs[64]` (view controller state) ran out after ~3 flips (the Upgrades yard creates ~31 view controllers per visit, the tech shop more); now 16384, nib registry 16384 too.
   - **Startup freeze / 'not responding'.** Two causes. (1) `sub_8c238` (id-string helper called while the first loader thread parses the unlock list) scans for the first digit with no bound; for `"tut"` it relies on stray digits in the heap past the string, which the zeroed arena never has, so it walked ~300 MB (~70 s). `cpu.c` hooks `0x8c2e0` and takes the loop's 'found past the end' exit. (2) `thread_slice` passed `us * 1000` to `uc_emu_start` (microseconds), so the 'time slice' was 14 s. Do NOT fix (2) with short slices: preempting the level loader mid-load leaves the level half built (white terrain, white map). Loader threads now run until they park or finish (5 s safety cap, `RA_SLICE_US`). Long guest runs (texture RGBA->565, JSON) pump SDL events from the HLE entry (`sdl_keepalive`) so the window manager does not flag it. `RA_STALL=1` logs gaps >250 ms between event pumps; `RA_THRPC=N` samples loader thread PCs.
   - **Scrolling.** UIScrollView content (tech shop, upgrades yard) now pans by touch-drag (8 pt threshold cancels the tap on the item under the finger) and by mouse wheel; offsets are clamped to `contentSize` (or the extent of the children). `RA_UIDUMP` prints `scroll off=`.
   - **Garbage collector (guest heap).** The host never frees ObjC objects, and the game creates strings/arrays/numbers/dictionaries every frame (profile: `objectForKeyPath:` splits, `stringWithFormat:`, ...), which leaked ~8 MB/min and exhausted the heap in a long session (user log: "guest heap exhausted", then `operator new failed`). `host/cpu.c` now has a conservative mark-and-sweep collector for the host's Foundation value objects (tagged `GF_CAND` in `new_obj`; kinds string/number/array-set/dictionary; buffers carry an owner tag so they are freed with their object; `gm_realloc` keeps the owner). Roots: all non-collectable heap blocks, the guest image, the fake region, guest stacks, registers of every engine and parked thread, host `.data/.bss`, the host C stack and registers, and pinned objects (nib `made[]`). An unreachable object is quarantined for one collection before it is freed. It runs from `engine_poll` after the heap grew 32 MB (and 300 frames). In a level run it freed 230,000 objects (26 MB) in one pass and the heap stopped growing. Knobs: `RA_GC=0` off, `RA_GCSTRESS=N` collect every N frames and poison freed memory (the full test suite passes 28/28 that way), `RA_GCLOG=1`, `RA_HEAPPROF=1` (allocation call sites), `[heap] N MB used` at the screenshot. Still leaked: guest-class ObjC instances (Texture2D, view controllers), host UIKit objects, `images[]` slots - they need real reference counts. Arena is 1.5 GB as a backstop.
   - **Fixed: Airbase (and every other level whose map is not in the IPA) (2026-11-13).** The IPA only ships a few map packs; the rest (`maps/map_<id>.xml` + theme art) the game downloads from `http://levels.tower.on-5.com/<id>.zip` (list in `userData.tower_files`). That server is still online, so `tools/fetch_levels.sh` mirrors all 63 packs into `levels/` (committed on purpose, see CLAUDE.md) and `host/main.c` links them (file by file with `cp -rs`, bundle first) into `<docs>/downloads/maps`. Airbase = location 23 = config 66 = map 721 (`urban/700/level21.*`); it plays. Note the first visit of a city shows an engine-drawn story screen ("Tap to continue"); the tap goes back to the map and you press the city and "Normal" a second time to start (this is also how the original behaves).
   - **Fixed: Spice shop "Free stuff" block removed** (socials, gifting and "check out an ad from our partners"): `is_free_stuff_block` hides the container (it needed the dead social/ad SDKs).
   - **Fixed: tech shop scroll padding.** The scroll view is authored 768x953 in a 1024x768 window, so its last rows hung below the window; `scroll_clamp` now lets it scroll by the hidden part plus the player bar (~80 px).
   - **Fixed: Career "Fitting room" button.** `-[CareerViewController openFittingRoom:]` only showed a "must be online" `UIAlertView` when `[[Session player] offline]` (the host has no UIAlertView), so nothing happened. `cpu.c` hooks `0x2d1ac` and takes the online branch; the dress room opens. Clothing previews live on `items.tower.on-5.com` (still online): `tools/fetch_levels.sh` mirrors them to `levels/items/` and the NSURLConnection stand-in serves them by URL path. Tiles were empty because the host's `-[UIImage initWithData:]` returned nil (now decodes via `image_from_data`); scroll views now always clip their content (the dress-room strip overflowed its panel) and pan by drag. Server audit: every URL in the profile is mirrored (63 level zips, 162 item images); the only other hosts are dead (`d2r0y9kezmx52z.cloudfront.net` thumbs, `on-5.com/i/logo.png` returns HTML) or ads/social.
   - **Fixed: main menu animations.** They are Core Animation (`CABasicAnimation`, `CAKeyframeAnimation`, `CAAnimationGroup` through `-[CALayer addAnimation:forKey:]`), which the host answered with nil. `host/uikit2.inc` now has a small CA engine (opacity, rotation, scale, translation, position, anchor point, timing curves, groups, repeat/autoreverse, delegate `animationDidStop:finished:`) evaluated per frame into a presentation overlay on the View (`ca_*` fields, applied in `draw_view`). `RA_CALOG=1` logs added animations.
   - **Open: menu "Intro" button.** `-[TowerViewController intro]` plays a movie fetched through `http://%@/intro.php` (engine server, dead); the video is not in the IPA and not on any host still online, so the screen stays black and returns to the menu. Needs the video file.
   - Open: a crash at the very end of a won level reported by the user (not reproduced: a failed level, "To the map!" and level-up in the headless run are fine); win screen path not exercised yet.
   - Still open: Training flyout icon (white orb instead of the castle icon), pause-menu confirmation dialog (Replay / To the map) is not drawn, finishing the level + unlock `tut`, win screen, audio. Older notes follow.
   - Remaining level work (older): tutorial prompts inside the level, tower placement/waves are untested beyond zoom/tap, audio, win/lose screens, and writing the result back to the career.
   - **Fixed: tutorial prompts and magic bar (2026-11-12).** `host_msg isKindOfClass:` returned YES for everything. `sub_fac04` (level config parser) does `if ([parsed isKindOfClass:[NSNull class]]) parsed = nil`, so every per-level `settings` dictionary was nil: no `tutorial` flag (so no `CTutorial`), no magic bar. `isKindOfClass:`/`isMemberOfClass:` now walk the real class chain (guest superclasses and the fake-class parent table). Scripted play-through now shows every prompt and each step reacts (see `docs/KNOWN_FUNCTIONS.md`). Drag-to-build: the ghost tower is drawn ~58 px above the finger, drop 58 px below the marker.
   - **Fixed: touches swallowed.** a clear plain `UIView` container at the bottom of the screen caught touches meant for the GL view (tower bar, pause menu); `hit_test` now ignores clear plain containers. A mouse click is held "down" for 4 frames because the engine polls the touch state once per frame (a quick click used to be lost, which made tutorial prompts impossible to dismiss).
   - **Loading screen animation.** the level loader thread now runs in ~14 ms time slices on its own engine (`thread_slice` in `host/cpu.c`) instead of blocking the main loop, so the loading screen keeps animating.
   - **Fixed: offline progress and level-ups (2026-11-12).** Offline the game rebuilds the player from the bundled starter profile on every launch and only merges `unlocks` back from the saved `AnonymousUserData`, so xp / level / spice / upgrades reset. The host now restores `xppoints, levelpoints, tonextlevel, level, specpoints, spice, rank*, up_*` from the saved copy once at start (`offline_restore_progress`). The server normally levels the player up ("You will level up when you get online!"); `offline_levelup_check` does it host-side before `updateUserInfo:` (`tonextlevel` = xp still missing; level L needs 10*L xp - a guess, the real curve is server side). The offline level-up bubble (blank white box + stretched label) is hidden.
   - Still open: map welcome prompt reappears after restart; loading-screen animation is frozen (engine `sub_f6eb0` frame appears to run only once - not yet traced).
   - **Fixed: tower bar.** `-[O5Globals deviceType]` returns 1 (iPhone) unless `[[UIDevice currentDevice] respondsToSelector:userInterfaceIdiom]` and the idiom is Pad; the host did neither, so the game used iPhone layout flags (`game+0x1dd`) but loaded iPad textures, and the bar looked up `icon_x2` (an `<iphone>1` texture) which does not exist. The host now reports an iPad. Result: tower bar with 6 towers and prices, "menu" button + Paused screen work, iPad-resolution map and menu art. Tower placement from the scripted harness still does nothing (icon tap + hex tap, and drag) - needs a real-mouse check.
   - **In-level state (older notes, partly superseded).** The game object exists and its per-frame update runs (`sub_d2768` -> `sub_d2ac6`..), the HUD top strip and the arena render. Missing compared with the device (see `ref-images/` and the user's reference shots): the bottom **tower bar** (only its 480 px left tile is drawn at y=721; tower icons for types 1,4,7,10,13,16 *are* loaded from `towers/towerN_icon.png` but no quads are drawn for them), the tutorial bubbles and the "build here" pointers, creeps/towers (no wave is running; the Training config has `wavedelay` 1000000, so waves are launched from the HUD).
   - Offline room data (`-[TDServer mod_joinGameConfig:]`) only carries `roomid status configid numplayers location map wavedelay gametype sources bases waves`; it has no `players` list and no `settings` (`dumbcreeps`, `build_around_base`, `tutorial`, `cam_x/cam_y`, `creep_hp`) nor `grantsunlock`/`msgwin`/`msglost` from `offlineConfigs`. The host now synthesises `players` (local player, slot 1) on the first miss (`offline_room_players`, uikit2.inc); `settings` and `grantsunlock` are still not forwarded - finishing the Training level needs `grantsunlock: "tut"` to unlock the next level.

(tower availability).

1. **Career persistence.** `NSUserDefaults` is now real and persistent (`<save dir>/defaults.bin`); the game stores the player profile backup, last location, tutorial flags and the request queue there. Verified: a second launch reloads the saved keys and plays the returning-player flow (intro splash -> map). Not yet verified: that xp / unlocks earned by finishing a level survive a restart.
2. Several screens are still 768 px wide inside the 1024x768 window (shop, career): the nib flag `UIAutoresizeSubviews` is False on nearly every view, so portrait-authored containers are not widened (ignoring the flag broke the landscape main menu, so it is honoured).
3. The tutorial bubble is now sized correctly (nib autoresize) and sits bottom-right as on the device.
4. Main menu shows some nib placeholder labels (`Intro sequence`, `progress: 0%`) that the device hides at runtime.
5. Audio is not implemented (OpenAL calls are silent stubs; CAF IMA4 + MP3 decoding needed).
6. GL performance is untuned (client-side vertex arrays; each GL call is an emulator trap).

## Tools added for this port
`tools/nibdump.py` (decode NIBArchive), `tools/objcdis.py` (disassemble an ObjC method with selector names), `tools/selxref.py` (who uses a selector), `tools/cgbi2png.py` (view CgBI assets), `tools/shot.sh` (headless run -> PNG + backlog), `tools/hle_todo.sh`. Debug env vars: `RA_TRACE=1|2|3`, `RA_UIDUMP=1` (view tree at the screenshot frame), `RA_FBOSHOT=1` (dump the game's render target), `RA_GLERR=1`, `RA_GLDUMP=1`, `RA_PROF=1`, `RA_FPS=1`, `RA_CLICKS=frame:x:y,...`, `RA_CLICK_HOLD=N`, `RA_DRAG=frame:x0:y0:x1:y1`.
